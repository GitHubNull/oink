### 4.2 X11 输入机制（`linux_input_probe.c`）

实测结论（数值为本次运行记录）：

- 普通按键：core 与 XI2 raw 都收到 2 次。
- 同步 passive grab + `XIReplayDevice`：拦截 1 次；拦截期间本地交付 0 次；Replay 后恢复 2 次。
- 远控主动 `XIGrabDevice` + `Swallow`：捕获 2 次；本地交付 0 次；解除后恢复 2 次。
- 原生已有的 pointer grab 存在时，第二连接抓取返回 `AlreadyGrabbed`（status=1）——不能靠抢占 GTK/Qt 源拖拽的 grab。
- 独立 XI master 注入：普通事件 `source=5`，注入事件 `source=11`；core 2 次、raw 2 次、XI2 2 次，`expected_source` 匹配。说明可以用 sourceid 区分自己的注入，不需要“全局时间窗吞事件”。
- 专属 XTEST slave 不能 reattach 到自有 master：X error 129。当前方案保留“独立 master + XTEST”。

仍未验证：物理 HID ↔ XKB 键位、左右修饰键、AltGr、自动重复、媒体键、加速/原始位移、精细滚动、触摸板手势、热插拔、锁屏/会话切换。完整触点注入是否必须引入 uinput/helper，尚未决策；**不得自行启用或先把未实现手势写成“已支持”**。

### 4.3 GTK 原生 XDND（`linux_dnd_probe.c`）

- Drop 分支：`begin=1 end=1`；`data_get=1 data_received=1 drop=1`；源按钮按下 1 次；合成 down/up 1/1；raw down/up 1/1；destination visits=2；`same_context_return=1`；原 grab 保持检查 4 次；幽灵 grab 释放检查 2 次。
- Escape 分支：`begin=1 end=1`；`failed=1 user_cancelled=1`；无 data/drop；Escape down/up 1/1；幽灵 grab 释放检查 3 次。取消在 ButtonUp 之前解除 grab。
- 关键结论：回到源位置必须保持**同一个 source context / 同一个原生 grab**，不能伪造新的 ButtonDown/Begin；Drop 数据走 XDND selection，不走 CLIPBOARD。
- **限制**：只验证 GTK 同进程局部机制。跨进程 catcher、Nemo、Qt、浏览器、产品网络 XDND 仍未验收。

### 4.4 私有音频（`linux_audio_probe.py`，PipeWire 1.0.5）

- monitor 自动路由前采样为 0；显式 `pw-link` 路由后捕获 65,280 samples，RMS 5792.56。
- sink mute 后 monitor 仍有 69,120 samples，但 RMS=0；解除 mute 后恢复。**生产不能直接依赖 sink 静音，也不能假设 monitor 不受 mute 影响。**
- `module-remap-source` 虚拟 source：`parec` 真实消费时 1 个 active output、>10,000 samples、RMS >1000。
- libpulse 流 cork/uncork：corked 时流仍存在，active=0、samples=0；uncork 后恢复。**source state 仍可能是 RUNNING，不能靠 source 状态判断“有人要麦克风”。**
- 消费者退出/断开后需求归零；原生 `pw-cat` 录音产生 2 条 active link、67,584 samples，且其消费者在 Pulse 列表中以 `object.serial` 身份可见（本次匹配 1 个），退出后归零。
- 本环境没有 WirePlumber，必须显式路由；这不等于所有用户桌面都必须显式路由，但生产实现不能假设自动连接。
- 仍未验证：真实物理麦克风、真实应用选择虚拟输入、设备拔插/音频服务重启、长时运行。

### 4.5 FUSE（`linux_fuse_probe.c`）

- 普通用户私有挂载被拒绝 `EPERM`。根因不是 `/dev/fuse` 权限或开发包缺失，而是代理进程继承 `NoNewPrivs=1`，setuid 的 `fusermount3` 被禁用。
- 探针现在会明确检测并输出该阻塞，不放宽安全设置。
- **尚未取得 FUSE 挂载通过证据**。需要在普通系统终端运行（见 §7.5），日志写入 `.release-tools/linux-probes/fuse-user.log`；用户执行后由代理自行读取日志，不要让用户重复描述。

## 8. 已知坑与平台限制

1. **禁止向真实桌面注入合成输入**：不要用 XTEST/xdotool 往 `DISPLAY=:0` 发键鼠；曾导致用户键盘失效。所有自动注入只在隔离 Xephyr/私有输入设备中。
2. **FUSE 与 NoNewPrivs**：代理环境 `NoNewPrivs=1`，setuid `fusermount3` 被禁用；这是已知阻塞，不是缺包。不要在应用内绕过或要求 root。
3. **PipeWire 无 WirePlumber**：本机私有实例必须显式路由；生产实现要处理有/无 session manager 两种情况，不能假设自动连接。
4. **sink mute 会静音 monitor**：音频探针已实测；源端静音/需求检测要按消费者身份与 cork 状态设计。
5. **source RUNNING ≠ 有消费者**：cork 后 source 可能仍 RUNNING；虚拟麦克风的开麦条件必须看有效下游消费者。
6. **原生 XTEST 身份**：独立 master 注入可被 sourceid 识别；专属 XTEST slave reattach 会 X error 129。不要把所有 XTEST 当作自己，也不要用全局时间窗吞事件。
7. **GTK 源拖拽 grab 不能被抢占**：已有 pointer grab 时并发 grab 返回 `AlreadyGrabbed`；DnD 回源必须保持同一 context，不能伪造第二次 ButtonDown。
8. **Xephyr keymap 差异**：`XK_F24` 在 Xephyr 无映射，输入探针已改用 `XK_F12`；写新探针时注意键位可用性。
9. **UI 主线程**：WebKitGTK/GTK 构建与窗口操作必须在 UI 主线程；后台 DnD 原生主循环在后台进程主线程；普通 worker 不能直接执行 GTK 闭包。
10. **Wayland**：本轮不实现。必须在启动时准确识别并解释限制；XWayland 不等于完整 X11 会话，不能启用部分全局输入后宣称支持。
11. **macOS/Windows 路径必须保留**：不要机械替换 `not(windows)`/`not(macos)`；逐个区分公共 Unix 行为与平台专属行为。
12. **单文件 ≤500 行**：新增源文件按职责拆分，不豁免；不要顺带全仓重构。
13. **同文件多 target 告警**：`oink-clipboard` 的 `src/lib.rs` 同时是 lib 和 integration-test target，`cargo check` 会告警；不要用删除/改名掩盖，按现有结构处理。
14. **编译基线不完整**：`cargo check` 在 `oink-locator` 停止，后面的 crate 未验证；修完 locator 后会暴露新错误，不要以为只剩 5 条。
15. **Node 版本**：系统 Node 可能是 24.22.1，仓库锁定 24.14.1；门禁必须用 `.release-tools` 的锁定 Node。
16. **Rust 镜像**：TUNA 对 1.99.0 曾 404；工具链已装好，不要重装/降级/改 `rust-toolchain.toml`。
17. **代理**：下载走 `127.0.0.1:7890`，本地回环加 `no_proxy`；`gh release download`/cargo/git 都需要显式 env。代理死掉时先确认代理，不要把网络问题误判为仓库问题。
18. **资源限制**：所有新构建/测试用 `systemd-run --user --scope` 限额；不要裸跑高并发 Cargo/Vitest。发生过的死循环/整机卡死事故要避免。
19. **sudo**：需要 sudo 的系统操作整理成脚本交用户跑；代理不尝试非交互 sudo，不修改全局配置。
20. **真实桌面手测**：全局输入、锁屏、物理拔插/热插拔、真实麦克风、Windows 配对等由用户执行；代理读取约定日志/截图，不让用户重复描述已观察到的现象。
